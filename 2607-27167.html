SpecFirst: Behavioral Specification Elicitation as a First-Class Step in Agent-Based Program Synthesis from Scratch

Yihao Chen, Shi Chang, Feng Lin, Khaled Chawa et al. · July 2026 · arXiv:2607.27167

SpecFirst offers a coherent, inspectable workflow and improves observed ProgramBench performance across four configurations. The decisive next step is to audit SPEC.md directly and use repeated, matched-resource controls to isolate its contribution from the larger pipeline.

Paper overview

SpecFirst studies black-box behavioral reimplementation of deterministic command-line programs. Given incomplete natural-language documentation and execute-only access to a reference binary, an agent must infer behavior and construct a compatible program from scratch — a setting where existing agents often begin coding before they have explored enough of the target's behavior.

The proposed workflow separates discovery from implementation. A dedicated specification agent probes the binary and records its findings in a six-part SPEC.md; a fresh-context synthesis agent then receives the documentation, binary access, and specification, and may re-probe ambiguous behavior while implementing the program. This combination of active execute-only elicitation, a specification-only agent, a persistent natural-language handoff, and fresh-context synthesis is distinct within the literature examined by the review.

The evaluation covers all 200 ProgramBench tasks with four model configurations from two families. On the observed runs, the complete SpecFirst package raises mean hidden-test pass rate for every configuration and reaches more reference-program lines during probing, while increasing mean per-instance cost by 48%–130%. These results establish a promising package-level pattern; they do not yet identify which component causes it or characterize run-to-run stability.

Key strengths

A consequential whole-program problem is sharply instantiated. Reconstructing a program from incomplete documentation and a behavioral oracle requires active experiment design, retention of interacting observations, and repository-scale implementation without source code as an architectural anchor. Hidden executable tests give the study an objective finite-suite endpoint.

The elicitation-to-synthesis integration is coherent and usefully distinct. The workflow gives behavioral discovery protected time, externalizes findings before coding, and provides the implementation agent with a stable reference in a fresh context. The contribution is strongest when described as this precise four-element integration rather than as a broad claim over specification-first development.

The handoff creates an inspectable research object. A persistent SPEC.md makes cross-agent knowledge transfer visible and, in principle, auditable. It also creates a practical interface for future replay, verification, caching, human review, and cross-model experiments.

The in-scope evaluation footprint is strong. The paper uses the complete 200-task benchmark, same-task comparisons, four model configurations, an unchanged downstream scaffold, network-isolated execution, and dense hidden behavioral tests. Using the full suite avoids favorable task selection in the main study.

The empirical reporting exposes useful trade-offs. All four observed configurations move in the same performance direction, and the paper supplements final pass rates with exploration coverage, task difficulty, work trajectories, failure categories, format comparisons, and explicit cost overhead. This diagnostic breadth makes the system easier to interrogate than a final-score-only study.

Key concerns and constructive suggestions

The defining specification contract is not independently validated. The specification agent decides when exploration is complete, the enforced gate checks only that SPEC.md exists, and the study does not measure claim correctness, behavioral completeness, contradictions, output-channel fidelity, or probe provenance across the corpus. To address this, the authors should build a claim-to-probe ledger, replay claims against held-out valid and invalid behaviors, and report independently adjudicated completeness, fidelity, contradiction, and traceability measures.

The main comparison bundles several causal changes. SpecFirst adds an agent, a mandatory phase, more probing and inference, structured external memory, a context reset, and substantially higher cost while retaining downstream re-probing. The observed contrast therefore identifies the complete workflow package, not the contribution of the specification artifact alone. To address this, the authors should run matched-token, matched-cost, and matched-query controls that cross specification presence, agent count, context reset, phase order, trace representation, and re-probing.

Run-to-run reliability and several headline inferences remain unresolved. The evaluation appears to contain one stochastic trajectory per task and condition, and the paper does not provide complete paired inference for upper-tail, difficulty, or process claims. Exact test details, paired effect magnitudes, multiplicity handling, and empirical run variance are also missing. To address this, the authors should repeat independent generations under archived settings and publish task- and run-level outcomes with paired intervals, interaction tests, threshold-transition analyses, and task/run hierarchical uncertainty.

The intermediate metrics do not yet validate the claimed mechanism. Executed-line reach measures which source lines a probe touches, not whether behavior was understood or recorded faithfully; source-line growth measures code volume, not productive implementation. Discarding the elicitation trace also hides uncertainty and rejected hypotheses, while downstream correction is not quantified. To address this, the authors should track each behavioral requirement from probe to specification to code and hidden test, compare specification-only, full-trace, and evidence-ledger handoffs, and measure re-probe corrections and contradictions.

Reproducibility and scope remain narrower than the framing. The dated artifact search did not locate the claimed patch set, exact prompts, immutable environments, raw outcomes, traces, specifications, or analysis scripts, and the evidence comes from one deterministic-CLI benchmark and one scaffold lineage. To address this, the authors should publish an immutable author-linked experiment package and then replicate across another scaffold plus a stateful or non-CLI oracle before extending claims to broader program construction.

What would most improve this paper

1. Validate SPEC.md as a scientific object. Attach replayable evidence and uncertainty to every behavioral claim, evaluate held-out positive and negative behaviors, and report contract correctness, completeness, contradiction, channel fidelity, and downstream mediation.

2. Isolate the mechanism with matched-resource controls. Compare the full workflow with equal-budget direct synthesis, a forced second pass without a specification, a single-agent required-spec condition, a two-agent no-spec condition, alternative handoff representations, and an oracle-spec upper bound.

3. Add repeated runs and complete paired inference. Archive generation settings, separate task and run variation, test every headline contrast directly, and report empirical paired magnitudes alongside accuracy–cost, accuracy–query, and accuracy–latency frontiers.

4. Release an immutable exact-run package. Provide patches and commits, complete prompts, dependency locks, container digests, provider snapshots, raw per-task outcomes, command traces, SPEC.md files, subset identifiers, cost logs, and scripts that regenerate every table and figure.

5. Formalize and broaden the evidence boundary. Define observable behavior across stdout, stderr, exit status, filesystem effects, and state; distinguish finite-suite agreement from full equivalence; calibrate novelty language to the exact integration; and replicate in a different scaffold and oracle setting.
